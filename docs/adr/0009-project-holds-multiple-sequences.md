# 0009 工程持有多条序列，界面状态仍只有一份

## 状态

已接受（M9-T14 实现）。取代 M1-T07「一个工程 = 一条序列」的模型。

## 背景

多序列之前，`Project` 直接存一条 `Sequence`，`ui`（播放头、选中、工作区、缩放）、
撤销栈、导出计划都默认「整个工程只有这一条时间线」。要支持新建 / 切换 / 重命名 /
删除序列，必须决定：序列之间共享什么、各自持有什么、老工程怎么读进来。

## 决定

1. **工程持有序列列表与当前指针**：`sequences: Vec<Sequence>` + `active_sequence: Id`，
   至少一条；`sequence()` / `sequence_mut()` 按指针取当前序列，对外不暴露列表的可变引用。
   序列的 id 由工程级计数器分配，与每条序列内部的 `next_id` 是**两个独立的 id 空间**：
   不同序列里可以有同号的轨道 / 片段，只有 `(sequence_id, object_id)` 才唯一。
2. **工程格式升到 v2**：迁移函数把旧的 `sequence` 对象包成单元素数组、补上序列 id 与
   指针；没有 `version` 键或 `version < 2` 的都按老格式处理。`serde(default)` 只负责补
   字段，字段的语义搬运一律写在迁移里。加载时的自愈保证列表非空、id 不重复、指针有效。
3. **界面状态与撤销栈保持工程级一份**：切换序列时播放头归零、选中与工作区清空、
   撤销栈重置，缩放 / 滚动沿用当前视图。理由：`ui` 属于「正在看的那个位置」，放进纯数据
   模型会让 `Sequence` 依赖工程概念；不追求「切回来还停在原来的播放头」。
   **改这条的触发条件**：用户明确要求每条序列各自记住播放头 / 撤销步数。
4. **素材表、自动保存、工程打包仍是工程级**：所有序列共享一份素材登记，删素材前要数
   所有序列里的引用，LUT 相对路径也要在所有序列上重算。
5. **导出计划按序列 id 定死**：打开导出面板时记下当时的序列 id，确认时按这个 id 生成
   计划；队列项带 id。理由：计划本来就是快照，但文件选择框期间序列可能被切换，
   只靠「当前序列」会把 B 序列导成 A 的成片。

## 考虑过但没选

- **每条序列各自持 `UiState` 和 `UndoHistory`**：语义更漂亮，但要把播放头、选中、缩放、
  撤销全部塞进 `Sequence`，且切换时 `history` 要按 id 索引；本阶段收益不抵改动面。
- **保留 `sequence` 字段作「当前序列」，另存一个列表放其它序列**：现有 200 多处引用
  都不用改，但同一份数据有两个权威来源，保存 / 自动保存 / 撤销都得先合并，容易写坏工程。
- **不升版本、只靠 `serde(default)`**：老工程会反序列化出空列表，读进来像空工程。

## 后果

- 所有 `project.sequence` 改成 `sequence()` / `sequence_mut()`；`asset_clip_count`、
  `repath_luts`、`sanitize` 从「一条」变成「遍历全部」。
- 切换序列会标出未保存改动（指针是工程内容的一部分），保存后下次打开停在同一条序列。
- 队列里的导出任务与序列 id 绑定；序列被删掉后仍按入队时的快照导完，只是提示里
  可能显示一个已经不存在的名字（保留名字字符串，不回查工程）。
