# 0010 GPU 合成后端（M10-T02）：接口先落，实现押后

## 状态

**部分落地**。`M10-T02` 的「可以换后端」这一层已经进了代码（`player::compositor::backend`），
GPU 实现本身没做，任务是**阻塞**状态，不是完成状态。

## 背景

ADR 0008 定的路线是 A（多实例 + CPU 合成）先落地、B（多实例 + GPU 合成）随后，
A 永远保留为回退。`M10-T01` 已经把 A 做完：`player::compositor` 每路一个 mpv，
SW 渲染到同尺寸画布，CPU 逐像素叠。

`M10-T02` 的验收是「1080p 两路 60fps、三层不丢帧」，这必须在**有显卡的真机**上逐帧比对，
而当前开发环境没有可验证的 GPU 路径：

- `MPV_RENDER_API_TYPE_SW` 拿的是 CPU 内存里的帧，要走 GPU 就得换成
  `MPV_RENDER_API_TYPE_OPENGL`（要有 GL 上下文）或者 D3D11 共享纹理，两者都要和
  gpui / wgpu 的设备与队列对上；
- 三平台各一套互操作（D3D11 / Metal / GL），且「错一帧」的表现是画面颜色或对齐不对，
  拿不到真机就是不可验证的改动；
- 现有 CPU 路径的瓶颈主要在 mpv 的软件解码，不在 blend：1080p 两路混合约 8 MB/帧，
  30fps 只有 240 MB/s 的写入，远不是热点。把 blend 挪到 GPU 换不来多少帧率，
  **真正的收益在「解码后的帧不上 CPU」**，那要动的是解码路径，风险高得多。

## 决定

1. **先把「谁来叠这一帧」抽出来**：`Backend::{Cpu, Gpu}` + `detect`，用
   `NGY_COMPOSITE_BACKEND=cpu|gpu` 选择。现在只可能返回 `Cpu`；显式要求 `gpu` 时
   退回 CPU 并给一句人话说明（不静默降级——否则测的人以为测的是 GPU 路径）。
2. **GPU 实现押后到有真机可验证的时候**，验收保留为「1080p 两路 60fps、三层不丢帧、
   与导出同一时刻构图一致」。真做的时候只需要改 `backend.rs` 里返回 `Gpu` 的分支，
   合成线程的其余部分（图层管理、seek、背压）不用动。
3. **CPU 路径不因为等 GPU 而减配**：两路仍然按同一画布尺寸渲染，超出 `MAX_LAYERS`
   的轨道不参与并提示。

## 后果

- 用户看到的还是 CPU 合成：两路 1080p 可用，三路以上只叠最上面两路。
- 排障时有明确入口：`NGY_COMPOSITE_BACKEND=gpu` 会把「为什么没走 GPU」写进日志与横幅。
- `M10-T02` 在 TODO 里标 `[~]`（阻塞），不标 `[x]`；`CURRENT_STATE.md` 的「未验证」
  一节要写清「没有在带显卡的机器上验过」。

## 未决问题

- Windows 上走 D3D11 共享纹理还是 OpenGL 上下文？前者与 wgpu 的 D3D12 后端之间要跨
  设备拷贝，后者要自己维持 GL 上下文，两条都要先在真机上打表。
- macOS 是等 mpv 的 Metal 渲染，还是 OpenGL → wgpu 桥？
- 超过 4 路的时间线是否直接放弃实时、强制走渲染缓存（`M10-T19`）？
