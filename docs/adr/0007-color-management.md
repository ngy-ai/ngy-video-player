# 0007 色彩管理：工程统一 SDR，HDR 素材在边界处转

## 状态

已采纳（M5-T01）。

## 背景

素材里既有 SDR（bt709）也有 HDR（PQ / HLG，常见于手机、相机与流媒体源）。时间线
允许把它们混在同一条序列上，导出与预览因此必须对「什么时候转、转成什么」有统一
答案，否则同一段素材在预览和成片里会是两个颜色。

## 决定

1. **工程与成片的色彩空间固定为 SDR / bt709。**
   时间线不引入「HDR 工程」这个概念：成片一律 `-pix_fmt yuv420p`，矩阵 bt709。
   理由：HDR 输出要么依赖平台 HDR 管线（三个平台三套实现），要么在 SDR 显示器上
   看起来发灰；这个工具的产出是给人看的 mp4，不是母版。

2. **转换发生在素材边界，不在序列边界。**
   某段素材被判定为 HDR 时，只在这一段的滤镜链尾插 HDR→SDR，其余片段原样通过。
   判定看传递曲线：`ColorTags::tags` 里出现 `smpte2084`（PQ）或 `arib-std-b67`
   （HLG）才算 HDR。只看 `bt2020` 矩阵不够——有些转码工具会把 SDR 素材也打上
   bt2020，误判会让整条片子白白多一道浮点转换。

3. **导出链**（`src/timeline/export/plan.rs` 的 `HDR_TO_SDR`）：

   ```
   zscale=t=linear:npl=100,format=gbrpf32le,
   zscale=p=bt709,tonemap=hable:desat=0,
   zscale=t=bt709:m=bt709:r=tv,format=yuv420p
   ```

   顺序不能换：先线性化再换原色，然后才 tonemap，最后回到 bt709 编码。

4. **预览侧对齐**：程序启动时给 mpv 下发 `tone-mapping=hable`。mpv 自己会在
   HDR 源 + SDR 目标时插入 tonemap，曲线默认是 `auto`；显式钉成 hable 是为了和
   导出那条链一致——否则预览里调好的曝光导出来会变一个样。

5. **不做逐片段的自定义 LUT / 色彩覆盖**。需要调色的素材请先在外部做好再导入。

## 后果

- 混 HDR 与 SDR 素材的片子可以直接剪，不必先批量转码。
- 成片永远是 SDR；想要 HDR 母版目前需要走外部工具。
- 探测结果缺失（老工程、从未重链过的素材）按 SDR 处理：宁可不转，也不要对
  一段本来就是 SDR 的素材多插一道浮点链。
- 预览是单路解码，只显示最上面那条轨（见 M4-T02），所以「同屏两段不同色彩空间」
  的预览效果本身不可见；这个差异只能靠导出验证。
