# 小窗顶替主窗口，成为任务栏上的那一条

小窗模式的定义是「同一时刻只有主窗口或小窗之一可见」。谁挂在任务栏上，决定了「点任务栏」这个手势落在哪里。

早先的做法是让主窗口留着那一条、小窗用 `WS_EX_TOOLWINDOW` 不进任务栏。问题是：点那一条时，Windows 必然先把主窗口还原，再交给我们处理——系统画的这一帧躲不掉，用户看到的就是主窗口闪一下再消失。Win32 没有「拒绝还原」的入口：拦 `WM_SYSCOMMAND` 不管用，任务栏走的是内部还原路径，压根不发这条消息；事后再怎么同步最小化，也只能缩短、不能消除那一帧。

所以反过来：任务栏那一条归小窗。

- 进入小窗模式时把主窗口**藏起来**（`ShowWindow(SW_HIDE)`，见 `platform::window::hide`），它连同任务栏、Alt+Tab 里那一条一起消失。藏不是最小化：位置、尺寸、最大化状态都留着。放它回来要用 `SW_SHOW` 而不是 `SW_RESTORE`——后者对藏起来的最大化窗口会顺手取消最大化（实测），`bring_to_front` 因此按「最小化 / 藏着 / 已显示」三种状态分开处理。
- 小窗改用 `WindowKind::Normal` 建成普通窗口，接管任务栏与 Alt+Tab。点那一条时系统要还原的是小窗本身，没有中间态，也就没有闪烁。
- 应用始终保有一条任务栏记录，不会出现「小窗被别的窗口盖住后无处可点」的死角；取消置顶（图钉）只改 Z 序，与任务栏无关，任何时候都还是那一条。
- 小窗被系统关掉（Alt+F4、任务管理器）时主窗口必须放回来（`mini_closed` → `reveal_main`）：播放器不能以「一个窗口都没有」的样子留在后台。
- 小窗不再自己「召回」自己（`MiniPlayer::recall` 只在没有任务栏入口的平台注册）。它是普通窗口之后，最小化、还原、被显示桌面收走全归用户说了算；还去抢着还原，只会让「点任务栏最小化」和「显示桌面」变成闪一下又弹回来。
- 小窗仍然没有系统装饰：`titlebar: None` 在 Windows 后端等价于 `hide_title_bar`，悬浮条与控制栏照旧自绘。任务栏按钮上的文字是窗口标题，所以小窗只在下发标题变化时才 `SetWindowText`。

## Consequences

普通窗口带 `WS_THICKFRAME`，于是小窗四边都能拖了（早先只有上边缘，因为工具窗口没有这条样式），代价是 Aero Snap 也能把它最大化。宽度本来就有上限（`mini_width` 按屏幕宽的 40% 收敛），下次开窗会自己恢复，所以不额外拦截。

`platform::window::can_hide` 只在 Windows 上返回 true。macOS 点 Dock 图标、X11 点应用图标都不会把最小化的窗口翻出来，没有闪烁问题，那边保持「主窗口最小化 + 小窗是工具窗口」的老组合——为统一而多写一套未经验证的 `orderOut` / unmap 路径，风险大于收益。两条路径在 `open_mini` 里由 `can_hide` 分叉，其余逻辑共用。
