# 影匣 · ngy-video-player

跨平台**视频播放器 + 视频剪辑器**。界面用 [gpui-kit](https://crates.io/crates/gpui-kit)
（Zed 的 GPUI），解码交给 libmpv。Windows / macOS / Ubuntu 同一套代码。

## 项目目标

两件事，按这个顺序推进：

1. **放好**：任何格式、任何来源的片子都能直接播。这一步是地基，已经基本完成——
   解码、音视频同步、字幕排版全交给 libmpv，外面补上播放列表、音轨/字幕切换、
   截图、示波器、镜头分割。
2. **剪好**：**从零编排成片**。判断标准不是「有几个导出工具」，而是这条链路是否
   走得通：新建工程 → 导入素材 → 拖上多轨时间线 → 剪接 / 转场 / 效果 / 关键帧 →
   调音频与字幕 → 导出成片；工程存得下，下次打开能接着改。完整的手工验收剧本见
   [TODO.md](TODO.md) 的附录 A。

现在的位置：`.ngyproj` 工程能新建、打开、保存，**新建时选分辨率与帧率**（之后也能改），
素材从素材库拖上多轨时间线，落点默认覆盖、按住 `Shift` 是插入，片段可拖动、**两端可修剪**
（`Alt` 波纹修剪、`Shift` 拖右端是滚动编辑，`Alt` / `Ctrl` 拖中部是滑移 / 滑动）、切割、
删除（含波纹删除）、在接缝上加转场（类型与时长都能调），试听原片时能按**三点 / 四点
编辑**把一截素材插入 / 覆盖到播放头或工作区（落点轨道由轨道头上的图钉决定），
导出走 ffmpeg 的多轨叠加与混音，预览能按序列时间连续播放，两条视频轨能按不透明度叠着看、
多条音频轨能同时出声（各带音量与独奏）；
效果栈、关键帧、变速、调色、字幕图层与多序列都已接进这条链路。
两条视频轨的叠加预览已经落地（CPU 合成，两路），还缺 GPU 合成后端与其余专业剪辑能力。
差距清单、阶段顺序与任务规则写在 [TODO.md](TODO.md)，验收判据是它的附录 A。

技术分工不变：**剪辑的渲染同样交给 ffmpeg**——时间线编译成一条 `filter_complex`
再编码一次，本仓库负责时间线数据、交互与任务编排。不自研编解码器，也不追求
Resolve / After Effects 那种级别的合成与调色。

## 为什么是 libmpv

「支持所有已知的视频格式」这件事没有捷径：格式的复杂度不在播放器，而在解复用器、
解码器、色彩转换和字幕排版里。自研一条能覆盖 MKV/H.265/AV1/蓝光/网络流的路，
等于重写一遍 FFmpeg。

所以分工是这样的：

| 层 | 负责 | 为什么 |
| --- | --- | --- |
| gpui-kit | 窗口、布局、输入、文字渲染 | 跨平台一致的 UI 与输入处理 |
| libmpv | 解复用、解码、音视频同步、音频输出、字幕（libass） | mpv 的格式覆盖面就是 FFmpeg 的覆盖面，再加蓝光、网络协议、字幕样式 |

libmpv 内置了完整的 FFmpeg 与 libass，因此「能放什么」直接等于 mpv 能放什么：
MKV / MP4 / MOV / AVI / WMV / FLV / TS / M2TS / MPEG / VOB / OGV / 3GP / RMVB /
WebM / MXF / 各种 ISO 蓝光原盘，以及 H.264 / H.265 / AV1 / VP9 / ProRes / DNxHD /
MPEG-2 等编码；纯音频（FLAC / APE / DSD / Opus / AAC / MP3 …）也走同一条路。

## 取帧方式：软件渲染而非 GL 互通

mpv 的 render API 支持把解码结果直接渲染到一块 CPU 内存（`MPV_RENDER_API_TYPE_SW`）。
我们用这条路，而不是共享 OpenGL 纹理给 wgpu：

- **不需要 GL/wgpu 互操作**，三大平台的窗口系统差异全部绕开；
- 每帧只多一次内存拷贝（1080p 约 8MB），换来三平台行为完全一致；
- 渲染目标尺寸 = 画面在窗口里实际占的**物理像素**，且不超过视频原始分辨率，
  等于把缩放做在 mpv 内部（swscale 质量好），GPU 侧只做 1:1 贴图。

代价是 4K/120fps 这类极端场景会被 CPU 拷贝拖住。真到那一步，可以按同样的接口
再加一个 D3D11/GL 零拷贝后端，UI 层不需要改。

## 构建

```bash
# 1. 准备 libmpv 与 ffmpeg（放到 libs/<平台>/）
./scripts/fetch-libmpv.sh
./scripts/fetch-ffmpeg.sh

# 2. 编译运行
cargo run --release -- path/to/video.mkv
```

### 打包：一个 exe

release 构建会把 `libs/<平台>/` 里的 libmpv 与 ffmpeg **内嵌进可执行文件**，所以
`target/release/ngy-video-player.exe` 本身就是完整分发包：拷到任何一台没装过 mpv、
也没装 ffmpeg 的机器上都能直接播、直接裁切片段。

```bash
./scripts/fetch-libmpv.sh   # 库放到 libs/<平台>/（只需一次）
./scripts/fetch-ffmpeg.sh   # 可执行文件放到另一个目录（同样只需一次）
cargo build --release       # 产物约 220MB：约 116MB libmpv + 约 90MB ffmpeg
```

首次启动会把内置的库与 ffmpeg 解压到用户缓存目录，之后直接复用：

| 平台 | 落点 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\ngy-video-player\libmpv\`、`...\ffmpeg\` |
| macOS | `~/Library/Caches/ngy-video-player/libmpv/`、`.../ffmpeg/` |
| Linux | `~/.cache/ngy-video-player/libmpv/`、`.../ffmpeg/` |

文件名带内容哈希（`9665c142b49567cc-libmpv-2.dll`）：换了版本会写出新文件，
旧的在下次解压后清掉，不会误用上一版的库。

exe 也不依赖系统里的 VC++ 运行库：Windows 目标在 `.cargo/config.toml` 里静态链接
MSVC 运行库（`+crt-static`），干净系统上双击就能开，不会弹出「由于找不到
VCRUNTIME140.dll，无法继续执行代码」（见 `docs/adr/0006`）。

- debug 构建不内嵌（开发期 `libs/` 就在手边，每次链接搬上百 MB 没有意义）；
- `NGY_EMBED_MPV=<路径>` 指定要内嵌的库，`NGY_EMBED_MPV=0` 关掉内嵌，
  做出「库放在旁边」的轻薄 exe；`NGY_EMBED_FFMPEG` 对 ffmpeg 同理；
- 内嵌只搬 libmpv 本身：Windows 的 `libmpv-2.dll` 是自包含的，macOS/Linux 从
  Homebrew / 发行版拿到的库还依赖同目录或固定路径上的其它共享库，跨机器分发请
  继续用 `bash scripts/bundle-macos.sh` 生成的 `.app`。

### libmpv 从哪来

程序**不链接** libmpv，运行时按顺序查找（见 `src/player/ffi.rs`）：

1. 环境变量 `NGY_MPV_LIB` 指定的文件；
2. 可执行文件所在目录；
3. macOS 的 `Contents/Frameworks`；
4. `libs/<平台>/`（`windows-x86_64` / `macos-arm64` / `linux-x86_64` …）；
5. 系统加载器路径；
6. 编译期内嵌的那一份（release 构建，见上节「打包：一个 exe」）。

| 平台 | 库文件名 | 获取方式 |
| --- | --- | --- |
| Windows | `libmpv-2.dll` | 脚本自动下载 [zhongfly/mpv-winbuild](https://github.com/zhongfly/mpv-winbuild) 的 dev 包 |
| macOS | `libmpv.2.dylib` | `brew install mpv`，脚本会复制到 `libs/macos-*/` |
| Ubuntu | `libmpv.so.2` | `sudo apt install libmpv2`（或 `libmpv-dev`） |

库缺失时窗口照常打开，界面上会直接写明缺哪个文件、三条解决路径分别是什么——
而不是启动就崩。

## 用法

```
ngy-video-player [选项] [文件或目录...]

  -f, --fullscreen   以全屏启动
  -h, --help         帮助
  -V, --version      版本
```

拖入文件、目录、`.m3u`/`.m3u8`/`.pls` 播放列表都可以。拖到画面区按「打开」处理：
文件并进「默认」页，**打开文件夹**会新开一页列表，页名就是文件夹名，里面连同子文件夹
一起展开成树形：每层文件夹在前、按自然序排列（`第2集` 在 `第10集` 前面），点文件夹行
展开或收起，收起后里面的项也不再参与「下一集」。

拖到右侧列表面板（或某个页签上）按「添加」处理：文件并进当前显示的那一页，拖到哪个
页签就进哪一页，文件夹也整棵并进这一页，不会跳回「默认」。面板标题栏「添加」里的
**添加文件夹**和这个行为一致。

拖动行可以调整顺序，也能搬家：落在文件夹上下两端是插到它前面/后面，落在中间是把这一项
（文件夹则连同里面的东西）移进那个文件夹。按「打开」拖入单个文件时同目录的其它媒体会
自动排队；从列表面板拖入属于「添加」，只加拖进来的那些。

页签上右键可以重命名或删除这一页列表；右上角的 × 是同一个删除，只剩一页时不让删。

标题栏的折叠按钮可以一键收起 / 展开所有文件夹（收起后显示成「展开」，排序菜单里也有
同样两项）。收起的文件夹里的项既不出现在列表上，也不参与「下一集」。

### 工程模式（剪辑）

菜单栏按模式分成两套。播放模式是「文件 / 编辑 / 播放 / 字幕 / 音轨 / 视图 / 设置 / 帮助」：
「文件」只放打开文件、打开文件夹、新建 / 打开工程与退出；裁切、格式转换、换音轨、
内嵌字幕、章节元数据、代理、双机位与列表拼接这些针对当前文件的工具都收在「编辑」里。
剪辑模式换成「文件 / 编辑 / 预览 / 视图 / 设置 / 帮助」：「文件」只管工程的新建、打开、
导入、保存、收集素材、导出与关闭，不再有打开文件或单文件工具；「编辑」换成撤销 / 重做、
切割、删除、标记、工作区入出点与加轨，「预览」放预览播放、跳转、截图与示波器。

播放模式的「文件 > 新建工程」或「打开工程…」进入工程模式：上方是预览，下方是时间线
（标尺、播放头、视频/音频轨道）。拖入 `.ngyproj` 或从命令行传入也会直接进工程模式。

新建工程先弹「序列规格」：分辨率给 1080p / 4K / 竖屏三档预设，也能直接填宽高（必须为偶数，
`yuv420p` 没有奇数边的色度取样）；帧率给 23.976 / 24 / 25 / 29.97 / 30 / 50 / 59.94 / 60
八挡。素材库里有带画面的素材时，「按第一个素材创建」一键抄它的尺寸（按旋转后的方向）与帧率。
建好之后「文件 > 序列规格…」还能改：只换像素与帧对齐，片段的时间一个都不动，
改这一下和其它编辑一样进撤销栈。


时间线标尺与标题条区域可以横向滚动；轨道多到一屏放不下时，轨道区里上下滚轮是
「换轨道」，按住 `Shift` 滚动才是横向滚时间轴（轨道没溢出时滚轮照旧横向滚），
触控板的横向滑动不受影响。`Ctrl/⌘ + 滚轮` 以鼠标位置为锚点缩放，缩放范围
从「1 像素 = 1 帧」到「1 像素 = 10 秒」；标尺刻度随缩放自动换挡，拖动标尺移动播放头。
`-` / `=` 以播放头为锚点各缩一级，`0` 让整条序列刚好铺满面板。轨道多到一屏放不下时，
右端会出现一条可点的滚动条；加轨之后视口自动跟到最后一屏。剪辑模式的「文件 > 关闭工程」
回到纯播放器。

「文件」菜单里，「打开工程…」下面会列出最近用过的 5 个工程，点名字直接打开。`.ngyproj`
也会跟着媒体扩展名一起注册到系统里，双击工程文件就能进工程模式。

「文件 > 收集素材到工程目录」把工程用到的素材复制到工程文件旁边的 `<工程名>_assets/`，
再把工程里的路径改成相对路径。收藏完之后整个文件夹可以整包拷到另一台机器上直接打开，
不用再管原素材散在哪几个盘。

「文件 > 保存工程」用 `Ctrl/⌘ + S`，另存为用 `Ctrl/⌘ + Shift + S`；新建的工程还没有
落点，第一次保存会自动转成另存为。新建 / 打开 / 关闭工程以及退出程序时，如果有未保存
改动会先问「保存 / 不保存 / 取消」，标题条上的 `*` 表示当前有未保存改动。缩放与横向
滚动位置也跟着工程存，下次打开还停在最后看的地方；轨道的垂直滚动只在本次会话里保留。

工程落过盘之后，编辑停手 30 秒会自动在工程文件旁边写一份 `xxx.ngyproj.autosave`：
程序崩了不会丢活，下次打开这份工程时会先问要不要恢复。正常保存或正常退出会把它删掉；
不想要那份恢复记录的话选「否」，它会被改名成 `.autosave.rejected` 留着，不再提示。
还没保存过的新工程没有落点，也就不做自动保存——先按下 `Ctrl/⌘ + S`。

一个工程可以放**多条序列**：「编辑 > 序列管理…」里能新建、切换、改名、删除，列表上
写着分辨率与片段数，当前那条带「（当前）」标记。新序列沿用当前序列的分辨率与帧率，
要改规格用「文件 > 序列规格…」；改名 / 删除都有确认，最后一条删不掉。切换序列会停下
播放、把播放头归零、清掉选中与工作区，并重置撤销栈——界面状态与撤销栈是工程级一份，
不跟着每条序列各存一套。序列列表、当前指针与序列里的片段一起随工程存盘，下次打开
还停在最后编辑的那条；老工程（v1）会自动读成「只有一条序列」，工程格式因此升到 v2。
导出面板记下打开时那条序列，文件选择框期间切走也不会导错；队列每项都带着序列 id。
不支持嵌套序列。

轨道名称下面最多有四个按钮：图钉把这一轨设成**编辑目标**（三点 / 四点编辑的落点，视频与
音频各记一个）；眼睛（视频 / 字幕轨）或喇叭（音频轨）把这一轨关掉——片段仍
留在时间线上，只是不参与预览与导出；锁把这一轨锁住，之后所有编辑操作都会被拒绝；垃圾桶
删掉整条轨道，视频轨、音频轨与字幕轨同样适用。字幕轨没有图钉（字幕条目自带归属）。轨道上还有片段 / 转场 / 字幕条目时会先弹
确认（内容会跟着一起删，删错了可以撤销），空轨直接删，锁定的轨道要先解锁。前两个状态随
工程存盘。

在轨道头上**右键**还会弹出一张轨道面板：音频轨有音量档位（-12 / -6 / 0 / +6 dB，点一下
落一步撤销）与**独奏**（开了之后别的音频轨都不出声，独奏优先于静音）；所有轨都能在这里
静音 / 隐藏与锁定。轨道头太窄，多一个常驻图标就挤成一排小点，所以这些收在右键菜单里；
当前开着独奏时名字后面有个青色的 `S`，音量不是 0 dB 时也会把分贝写出来。音量和独奏随
工程存盘，也进导出——预览听到的电平与成片一致。

相邻两段之间可以加**转场**：右键后段片段选「与左侧片段加转场…」，或直接点接缝上那道
青色的转场标记，弹出的小面板里选类型（交叉溶解 / 淡入淡出 / 擦除 / 滑动）与时长
（0.2–2 秒），每点一下落一步撤销。已在接缝上的转场，右键菜单变成「转场设置…」，面板里
多一颗「去掉转场」。能加多长由两侧余量决定——前一段的长度、后一段素材入点之前还剩多少——
面板底部会写「最多 X 秒」；点了超过余量的时长会被钳回去并提示，余量不足 0.1 秒则直接
拒绝（那种情况导出只会退化成硬切）。

片段上还能挂**效果**：右键「效果…」开一张小面板，可以叠去隔行 / 降噪 / 锐化 / 防抖 /
插帧 / 水印。效果按加入顺序串成一条滤镜链，先加的先生效——锐化放在降噪之后才有意义，
所以每行都能上移 / 下移。开关一下只是不生效，不用删了重加；强度分三档（弱 / 中 / 强），
插帧是 2–4 倍（输出帧率 = 序列帧率 × 倍数），水印默认打片段自己的名字，位置与字号能在
面板里换。每次改动各落一步撤销。

效果只作用于画面，而且只在导出时生效：预览还是一条原片，看不到降噪 / 锐化 / 水印
（预览侧的滤镜归 M9-T12）。工程里出现这一版不认识的效果名时不会打不开，加载后会提示
「N 个不认识的效果已跳过」，导出时也跳过它们。

想让一段画面自己动起来（推近、平移、淡入淡出），右键「关键帧…」：把播放头停到片段里
要动的位置，用 ＋ / － 调缩放、水平 / 垂直位置或不透明度，点「记」留下一个点；换个位置
再来一次，两个点之间就插值。曲线存的是**片段内相对时间**，拖片段、切片段都不会让动画
错位。属性下面列出已有的点，点一下删掉，删光后这个属性回到静态值。

面板下半截是**曲线编辑器**：横轴是片段内秒数、纵轴是属性取值，网格上标着刻度，折线就是
实际会插出来的值。每个关键帧画成一颗小方块，点一下把播放头挪过去；播放头落在哪一段，
编辑的就是那一段（缓动存在这一段的**起点**上）。缓动按段给，有五个预设——线性、缓入缓出、
缓入、缓出、强缓动——也可以拖那两颗手柄自己摆三次贝塞尔（`cubic-bezier(x1,y1,x2,y2)`，
控制点被夹在单位方格内）。曲线下方「复制曲线 / 粘贴到这里」把整条曲线搬到别的属性或片段上；
在画布空白处拖一个框，松手就删掉框里的点。

导出时缩放与位置合成一个 `zoompan`（以画面中心为锚点，输出仍是序列尺寸），不透明度写成
`fade`——它是淡到黑，多轨时下面那条轨也会被一起盖住（导出链是 yuv420p，没有 alpha 通道）。
关键帧在时间线的片段下沿画成白色小竖条，**可以直接拖**：左右拖动就是改这个点的时刻，
落点吸附到帧、越出片段两端会贴到端点，松手落一步撤销。一根竖条代表同一时刻的所有属性
（缩放 / 位置 / 不透明度），所以拖它是整组一起挪，不会只动某一条曲线。

**调色**在片段右键的「调色…」里：亮度 / 对比度 / 饱和度 / 色温各一颗 － / ＋，每点一下
10%（-100–100），另有「复原」一键回到原始色彩。色温走 `colorbalance` 的红蓝偏移；亮度、
对比度、饱和度合成一条 `eq`。还可以挂一个 3D LUT（`.cube` / `.3dl` / `.dat` / `.m3d`），
路径按工程目录存相对形式，跨盘符才写绝对路径。导出链的顺序是
`eq → colorbalance → lut3d → fade → 效果`：先调色再淡到黑，否则淡出来的黑会被亮度提亮；
水印与降噪排在最后，不会被调色一起染上。调色和效果一样只在导出时生效，预览看不到。

**字幕**在标题条的字幕按钮或「编辑 > 在播放头加字幕…」里创建：面板输入文字、用播放头设
起点 / 终点，样式可选字体（三档）、字号（12–96 px，4 px 一档）、颜色（白 / 黄 / 青 / 红 /
黑）、描边（0–8 px）与上 / 中 / 下位置。没有字幕轨时点「确定」会自动补一条；也可以先用
「编辑 > 加字幕轨」建轨，再在轨道空白处右键新建、点字幕块编辑、右键编辑 / 删除。同一条
字幕轨上的条目不能重叠；轨道隐藏时整条不进预览与导出。条目随工程存盘，改动各落一步撤销。
换行请在文字里写 `\N`。

预览里的字幕是压在画面上的一层文字，显示文字、颜色与大致位置；字体、描边和精确排版由
导出时的 libass 负责。导出面板的「字幕」一行决定怎么交付：**烧录**（默认）用 `subtitles`
滤镜把 ASS 排版画进画面；**软字幕**另存一条字幕轨，mkv 用 `ass`（样式完整）、mp4 / mov
用 `mov_text`（只保文字与部分样式）。只导工作区时字幕跟着裁断并从新的 0 秒重新起算。

工程模式左侧是**素材库**，点标题条上的文件夹按钮或「编辑 > 素材库」打开 / 收起。工程里
登记过的素材都列在这里：封面、名字、时长与规格（分辨率 + 帧率，或采样率 + 声道）。三个
入口都能往里加东西——面板上的「导入文件…」（可多选）、「导入文件夹…」（连子目录一起扫）、
以及直接把文件拖进窗口。同一个路径只登记一次；探测在后台逐个跑，几百个文件的文件夹也是
先出列表、再陆续补上时长与封面，进度写在面板上。搜索框支持中文输入，走一套小条件语法
（空格之间是「并且」）：裸词搜名字，`名称:` / `时长>` / `分辨率>=` / `帧率` / `编码:` /
`日期>` / `标签:` 指定字段，前面加 `-` 是否定，例如 `航拍 时长>60 -标签:废片`。
分辨率按长边比、日期按天比（`2026-11-01` / `2026/11/01` 都认）；切不出来的条件会红字写在
搜索框下面而不是被悄悄忽略。每行末尾跟着它的标签；框里写个词点「加标签 / 清标签」就给
选中的素材批量打 / 去标签。搜索框下面那条是**智能合集**：把当前条件「存为合集」存进工程
（存的是条件、不是结果，素材改了标签下次自动跟着变），点合集就把条件填回搜索框。
双击一行只在预览区放原片（空格控制播放 / 暂停），时间线与播放头一概不动；点「回到时间线」
或拖一下播放头就回来。选中一行后「移除所选」把它从素材库去掉：还有片段在用时会被拒绝，
并说明有几个片段在用；磁盘上的文件始终不动。文件被移走的素材标成「缺失」而不是从列表里
消失，被替换过的标「文件已改动」并重新生成封面。

试听原片时还能顺手做**三点编辑**：`Alt I` / `Alt O` 把预览区当前时刻记成源入点 / 源出点，
面板上写着源区间与将放多长；再用时间线的播放头当第三个点，`,` 插入、`.` 覆盖。新片段长度
就是源区间长度，工作区出点在那儿时按剩余空间截短并提示。源入出点只属于当前素材，不占用
工作区的 `Shift I` / `Shift O`。「回到时间线」或用 `Esc` 只收起试听、源区间留着，接着按
`,` / `.` 就能往别处放；「取消源区间」才是丢掉这一截。试听中方向键与逐帧挪的是原片自己的
时刻（要动播放头先回时间线）。

工作区的入点与出点**都定了**时，同一套按键升级成**四点编辑**：源区间塞进这段工作区，
时长取两者的短边（源更长就按工作区截短，工作区更长就只放到源尾、后面留空），提示会说清
是哪一侧短了；视频素材的声音这次会**一起**落到目标音频轨上，两段算一步撤销。落点轨道由
轨道头上的**图钉**决定：点亮哪条轨，素材就落到哪条（视频与音频各记各的），没点亮时按
「同类里第一条没锁的」挑；图钉状态随工程存盘，锁住的轨会自动跳过。

把素材拖到轨道上就是往时间线放片段：拖动时轨道上画一个落点框，框里写着「覆盖 / 插入」
与将要放多长，放不下的位置框是红的——纯音频拖到视频轨、没有音轨的素材拖到音频轨都会被
拒绝，松手时给出原因。落点会吸附到帧，也会吸附到相邻片段的左右边缘（差 8 像素以内直接
贴上去）。`Ctrl/⌘` 点击多选，一次拖多个时按素材列表里的顺序首尾相接，整批算一步撤销。

片段两端各有一条 6 像素的**修剪抓手**（悬停时看得出来），拖动它改这一端的入点 / 出点。
修剪**工具**决定「直接拖」走哪种语义，键位与常见 NLE 一致（标题条右侧常驻显示当前工具，
点它也能轮换）：

- `V` **修剪**（默认）：拖两端改入出点，同轨其它片段不动（可能留下空隙）；拖中部是移动。
- `B` **波纹**：同轨后面的片段跟着补位 / 让位，轨道上不留空隙。
- `R` **滚动**：只挪接缝，两侧片段一起变长短（拖右端且后面紧挨着另一段；拖左端没有接缝
  可挪，退回普通修剪）。
- `Y` **滑移** / `U` **滑动**：拖片段中部——滑移是位置与时长不动、素材内容左右挪，滑动是
  片段左右挪、两侧邻居跟着伸缩；拖到别的轨道上退回普通移动。

修饰键随时可以临时覆盖工具，不用先切：`Alt` + 拖 = 波纹修剪，`Shift` + 拖右端（后面紧挨着
另一段）= 滚动编辑，`Alt` + 拖中部 = 滑移，`Ctrl/⌘` + 拖中部 = 滑动。拖动中按下的修饰键在
松手时生效。片段上的光标跟着工具变（两端左右调整、体上抓手）。

拖动时轨道上画一条竖线标出会切到的时刻（带时间码），松手才落一步撤销（一次拖动 = 一步），
提示条写出前后长度。松手之后弹**双画面修剪窗口**：切点前后两帧 + 两帧的时间码，点窗口
任意位置关掉；取帧走一次 ffmpeg 单帧导出（后台线程），所以窗口是松手后才出现、拖动中不刷新
——拖动中实时抠两帧会卡。纯音频片段不弹窗口。还没做的是独立的修剪**工具模式**（现在四种
修剪靠修饰键区分，没有单独的按键切换）与抓手以外的修剪光标（见 [TODO.md](TODO.md) M10-T07）。

落点压到已有片段时默认是**覆盖**：区间里的内容被切掉（压住两端的片段收边或切成两段），
序列长度不变。按住 `Shift` 拖是**插入**：在落点切开后续片段、整条往后让出这段长度，
序列因此变长。拖已有片段换位置是同一套规则。删除片段默认留空隙，`Shift+Delete`
（剪辑模式右键菜单里也有「波纹删除」）删完让同轨后面的内容往前补，不留空隙。

「文件 > 导入到时间线…」选视频/音频，素材会登记进工程并插到播放头；播放头那里已经有
片段时自动排到序列末尾。有画面的进视频轨、有声音的进音频轨，锁定的轨道跳过。

点击片段选中（白色描边），`Delete` / `Backspace` 删除，点轨道空白处取消选中。右键片段
弹出菜单：在播放头处切开、删除、与左侧紧邻的片段加 / 去掉 0.5 秒交叉溶解、隐藏 / 静音
所在轨道、锁定轨道、删除整条轨道（有内容时同样先确认）。
`Ctrl/⌘ + Z` 撤销、`Ctrl/⌘ + Shift + Z` 重做，标题条上的两个箭头会亮起表示还有可退的步数。

片段可以拖着走：左右拖改起点，拖到另一条同类型轨道上就是换轨。落点会吸附到帧；
锁定轨道、跨类型轨道和会撞上已有片段的位置在松手时会被拒绝，并提示原因。

`Ctrl/⌘ + K` 或标题条上的剪刀按钮在播放头处切割：所有未锁轨道上跨过播放头的片段
各切一刀，切点正好落在同一帧上；播放头停在空白处时只提示「没有可切的片段」。

`Shift + M` 在播放头处放一个标记，同一位置再按一次删掉；标记在标尺上画成一条竖线，
随工程一起存盘。

`Shift + I` / `Shift + O` 在播放头处设工作区入点 / 出点，再按一次清掉。两点齐全时
标尺下沿会出现一条色带，区间随工程存盘。

标题条上的下载按钮先开**导出面板**：选编码器（H.264 / H.265）、画质（CRF 16 / 18 / 23）、
编码速度（fast / medium / slow）、音频码率（128 / 192 / 256 kbps）与字幕交付方式
（烧录 / 软字幕），再点「导出…」选文件名。
分辨率取工程设置，有工作区时只导入出点之间。参数只对本次会话有效；常驻的用法是起个名字
**存为预设**，落在配置目录的 `render-presets.json`，下次点名字就套用（同名覆盖，`×` 删除）。
预设文件缺字段或出现不认识的编码器名时按默认值降级，不会让整份预设作废。

导出在后台跑，标题条原地显示百分比与所用的预设名，旁边的 × 取消；失败时会把 ffmpeg 的
最后几行日志带出来。

任务跑着的时候再点导出不会被打发走：新的一次排到队尾，标题条显示「队列 N」，队列项各自
记着自己用的是哪套参数。一次只跑一条，某条失败只弹横幅，后面的接着跑；× 会连队列
一起清掉，不会悄悄接着导。

跟别的剪辑软件换手走 **OpenTimelineIO**：「文件 > 导出时间线为 OTIO…」把当前序列写成
`.otio`（轨道顺序、片段入出点、空档、转场与标记都在结构里），「文件 > 从 OTIO 导入…」
读一份 `.otio` 并**新建一条序列**切过去——不覆盖手上这条。字幕轨、效果栈、关键帧、
调色、片尾定格与轨道音量装不进 OTIO 的结构，统一塞在 `metadata.ngy` 里：本程序能原样
读回来，别的软件会忽略。导入时认不出的轨道类型、转场与效果会降级并写在提示里，
不会让整份文件打不开。

多条视频轨自下而上叠加（时间线上靠上的那条画在上面），多条音频轨用 `amix` 混成一条并
归一音量；关掉的轨道整条跳过。每条轨道会先补齐到序列总长，成片不会因为某条轨短而缺尾巴。
标题条上的 ⊕ / 喇叭按钮各加一条视频轨 / 音频轨；新轨追加在轨道列表末尾，加完自动滚到
看得见它的那一屏，提示里也会带上轨道名。

相邻片段之间的转场用 `xfade` 合成，溶接时长取「转场时长、前一段长度、后一段可往前多取的
素材」三者中最小的那个——素材头部不够就自动缩短，不会因为缺帧把成片时长算错。界面在加
转场时按同一条规则预钳一次，所以这里通常已经是能兑现的值；万一工程是从别处改出来的，
导出这一层仍然兜底。音频侧不做交叉淡化，两段之间仍是硬切。

HDR（PQ / HLG）素材在它自己的滤镜链里转成 SDR：`zscale` 线性化 + `tonemap=hable`，成片
统一 bt709；预览也下发同一条曲线，两边看到的曝光一致。判定只看传递曲线，纯 SDR 素材不会
多这一道浮点转换。边界与理由见 `docs/adr/0007-color-management.md`。

工程模式下拖播放头会直接把那一刻的画面送进预览：取帧规则在 `timeline::preview`，
和导出共用同一份「哪些轨参与输出」——静音 / 隐藏的轨跳过，轨道顺序靠上的优先。同一个
素材只 seek，跨到另一段素材才重新加载，所以拖着走不会一路黑屏。

素材比序列大（长边更长）、旁边又有 `<原名>.proxy.mp4` 时，预览改放那份代理：4K 素材在
1080p 序列里用原片预览往往卡成幻灯片。规则在 `timeline::proxy`（纯函数，导出侧也用它），
开关在设置窗口「播放设置」页，默认开；选中用着代理的片段时，时间线上会标出「代理」。
**导出永远用原片**——素材本身是 `*.proxy.mp4` 时导出会直接拒绝并说明，免得导出一个
低码率成片。

**渲染缓存**（设置窗口「渲染缓存」页，或菜单「设置 > 渲染缓存…」）解决另一半问题：预览
走的是解码链，效果、调色、推近只在导出时出现，预览根本看不到。点「为时间线补缓存」，
程序把「有启用效果 / 调过色 / 有关键帧」的片段按导出那条滤镜链单独渲成
`<素材名>-<指纹>.cache.mp4`，预览优先放它——于是预览看到的就是成片会是什么样。缓存文件
名里的指纹由素材路径、入出点、序列规格与效果 / 调色 / 关键帧参数算出，任何一项变了旧文件
自然不被命中；倍率不是 1x 或带片尾定格（缓存时间轴对不上）的片段不缓存。目录默认上限
4 GB（可调 2 / 4 / 8 / 16 GB），超出按最旧优先删；「清理缓存」一键清空。补缓存是一条
串行队列，进度就在这一页，随时可以取消。

拖动时预览还会**出声**（scrub）：画面停在那，mpv 接着把那几帧的声音放出来，指针停手
150 毫秒后自动收声。两处例外——多路合成时声音在各图层自己的实例里，主实例让出去了；音频轨
片段覆盖播放头时也不出声（那几路声音在各自的实例里，与 `J`/`K`/`L` 同一个道理）。

两条视频轨**同时有画面**时，预览会切到多路合成（`player::compositor`）：每条视频轨一个
mpv 实例，各自按同一块画布尺寸做软件渲染，再由 CPU 按不透明度叠成一幅——0 / 50 / 100%
与导出侧 `overlay` 同一套算法。只合成两路（`MAX_LAYERS`），三条以上只叠最上面两路并提示
一句；只有一条轨有画面时仍走原来的单路路径，不为它多养实例。合成中按 `S` 截的是这张
合成图（示波器同理），不再截某一路素材；单路序列仍交给 mpv 自己截。

空格或标题条最左边的播放键**连续播放**整条序列：播放头按真实时间走（跟着 `[` / `]` 的
倍速一起乘），走出一个片段就换下一个素材，走到序列结尾或工作区出点自动停下。再按一次
暂停，播放头留在原地；停在结尾时按播放从工作区入点（没设就是 0 秒）重来。播放中把播放头
拖到别处会先暂停——不然时钟会和手指抢播放头。方向键 5 秒、`Ctrl`/`⌘` + `←` `→` 逐帧都
改挪播放头，落点吸附到序列帧率。播放时视口跟着播放头滚，它不会跑出屏幕。

工程模式里 `J` / `K` / `L` 是剪辑器那套**倒放 / 停 / 正放**：`L` 每按一次 1×→2×→4×（到 4×
不再往上），`J` 反向同理、中途换向从 1× 重新起档，`K` 停下并回到原速。倒放没有声音——mpv
不能反向解码，画面靠逐拍 seek 往回追；多路合成时每图层也会跟着下发同一个倍速。按住 `K` 再点
`J` / `L` 是**逐帧**后退 / 前进（一次一帧，落点吸附序列帧率）。

标题条右侧的播放头读数就是时间码（`0:03.00 · 00:00:03:00`），点它、按 `Ctrl`/`⌘` + `G`，
或走「预览 → 跳到时间码…」都会打开同一块面板；输入 `时:分:秒:帧` 把播放头挪过去，也可以只写
`分:秒` / `秒`，29.97 / 59.94 的丢帧写法用分号（`00:01:00;02`）。超出序列长度停在结尾并提示。

预览的空档会压黑，转场则是以接缝为中心、两侧各一半时长先淡到黑再淡回来（接缝那一刻最暗）；
音频轨上的片段由**每条轨一路纯音频 mpv 实例**同时出声（最多四路，靠下的轨超出时提示一次），
混在一起的效果交给系统混音器；每条轨的音量（主音量 × 轨道增益）与独奏都在轨道右键面板里调，
与导出侧的 `volume` / 独奏规则同源，所以预览电平与成片对得上。声音会压住画面自带的那一路，
避免原声和音乐各走各的。画面仍只解一路（多轨叠加走合成器），这两条限制互不相干。

| `Z` / `X` | 字幕提前 / 延后 0.1 秒 |
| `M` | 静音 |
| `S` | 截图 |
| `I` | 播放统计（帧率、丢帧、延迟帧、解码丢帧） |
| `L` | 播放列表 |
| `O` | 打开文件 |
| `F` / 双击画面 | 全屏 |
| `T` | 迷你窗 |
| `A` | 打开设置（画面页） |
| `Delete` | 删除播放列表里选中的项 |
| `Esc` | 退出全屏 / 逐层关闭浮层（设置 → 菜单 → 播放列表） |
| `?` | 打开设置（快捷键页） |

播放菜单里有 A-B 循环：播到起点时点「标记 A-B 起点」，到终点时点「标记 A-B 终点」，
之后只反复播放这一段；换片或点「清除 A-B 循环」会取消。

单击画面本身是播放 / 暂停。控制条、菜单、播放列表这些浮层会把点击吃掉，
不会顺带把视频暂停——每个图标按钮和浮层容器都调用了 `stop_propagation`，
因为 GPUI 会把同一个点击派发给**同位置命中的全部 hitbox**，而不是只给最上层那一个。

截图（`S`）由 mpv 抓取解码后的原始画面，存到系统图片目录下的 `影匣截图/`
（Windows 问系统的「图片」库，重定向到别的盘也认；macOS/Linux 是 `~/Pictures/影匣截图`），
文件名形如 `视频名_01-23-45.png`，连拍多张也不会互相覆盖。截图失败只在 OSD 里说明原因，
不会打断播放。

存好之后画面左上角会浮出一张卡片：缩略图 +「复制 / 打开 / 定位」。复制在 Windows 与
macOS 上是把图片本身放进剪贴板，Linux 的两个后端只支持文本，那里复制的是文件路径
（按钮文案会写成「复制路径」）。鼠标停在卡片上时不自动收起，`Esc` 或右上角的 `×`
可以立刻关掉。

「播放 → 示波器…」对当前帧做三种统计，用来判断曝光与偏色：

- **亮度**：64 档直方图，配死黑 / 过曝占比；
- **波形**：横轴对应画面左右、纵轴是亮度，哪一片贴顶就是过曝；
- **矢量**：横轴 Cb、纵轴 Cr，越靠外饱和度越高，肤色应落在左上偏红的一条带上。

抽样在后台起一个 ffmpeg 进程，把画面缩到 160×90 读回原始像素再本地统计，不影响播放；
播放位置挪动后点「按当前位置刷新」重新抽。三种视图共用同一份结果，切换不重新抽帧。

「播放 → 镜头分割…」整片扫一遍，用 ffmpeg 的场景分数找出画面切换点：切点边扫边列，
点任意一条跳过去并暂停，方便核对镜头边界。灵敏度分「灵敏 / 默认 / 严格」三档，换档会
重扫；检测要解码整片，长片需要等一会儿，进度条与取消随时可用。

「文件 → 双机位并排导出…」把两个机位拼成左右画面：两路统一缩放补边到 640×360、统一
30fps，只取左机位的声音。右机位早开机时填「跳过开头」的秒数，也可以点「自动对齐」——
听两路开头 45 秒的声音做互相关，自动算出偏移；右机位晚开机时把两个文件交换一下即可。

### 裁切片段

菜单「文件 → 裁切片段…」在右侧打开裁切面板（与播放列表共用同一条通道，两者互斥），
播放不会中断。开始、结束可以手动输入（`90`、`1:30`、`01:02:03.500`），也可以边播边定位：
拖主控制条的进度条、空格播放/暂停、←/→ 前后 5 秒、Ctrl/⌘+←/→ 逐帧（面板上也有
「上一帧 / 下一帧」），停在哪一帧就点「设为开始 / 设为结束」，取的是播放器当前时间。
「预览片段」会从开始播到结束并自动停下，方便用画面和声音整体确认。

- 开始留空 = 从头开始；
- 结束留空 = 直到最后；
- 两端都留空 = 不裁切，按钮不可用。

面板里可以选导出参数：

- **导出方式**：精确重编码（切点精确到帧）或无损流复制（不重新编码，几秒完成，
  切口落在前一个关键帧上，可能比设定时间早几秒）；
- **编码与画质**：H.264 / H.265，高画质 / 标准 / 小体积三档 CRF；
- **画面处理**：HDR → SDR 色调映射、去隔行、降噪、锐化、恒定帧率（只在重编码时可用）；
- **音频**：EBU R128 响度标准化（-16 LUFS）、±5 秒音频偏移（0.1 秒步进，修音画不同步）；
- **轨道**：音轨、字幕、章节与元数据是否保留。

默认是精确重编码为 H.264 + AAC 的 mkv，字幕与多条音轨一并保留；输出到原文件同目录，
名字是「原文件名 - 片段.mkv」，已有同名文件时自动编号，不会覆盖。耗时与片段长度、
CPU 相关，进度显示在面板里，可随时取消。

参数调好之后可以在面板顶部「预设」里起个名字存下来（存在配置目录的 `presets.json`），
下次点名字一键套用；同名会覆盖，右侧 `×` 删除。

面板顶部的「来源」还能切到「文件夹…」：把同一套参数套到一整个文件夹（含子文件夹）上，
每个文件整段导出，落在源文件旁边、名字加「 - 批处理」，逐个串行执行并逐项回报进度，
可以随时取消。批处理不烧录字幕，也不做「删除中间段 / 分割」——这两项和区间绑定，
在整段导出里没有意义。

### 章节与元数据

菜单「文件 → 编辑章节与元数据…」打开编辑对话框：

- 标题 / 作者 / 备注直接改，留空表示保存时删除该项；
- 「在当前位置添加」以播放位置作为章节起点，时间框也能手输时间码
  （`90` / `1:30` / `01:02:03.500`，带帧号的 `HH:MM:SS;FF` 也认）；
- 章节按起点自动排序；两条离得太近（小于 0.1 秒）会被合并；
- 封面可以选一张图片，保存时以附件写进 mkv；不选则沿用原文件的封面。

保存走流复制：画面、音轨、字幕、附件都不重新编码，几秒结束；输出到同目录的
「原文件名 - 元数据.mkv」，原文件不动。内置字幕若是 mp4 的 mov_text，会转成 srt
才装得进 mkv；点阵字幕（PGS/DVD）与 ASS 原样保留。

输入框支持输入法与选区，中文标题可以直接打字。

### 其它导出入口

播放模式的「编辑」菜单里还有几项，模式统一：读入 → 调参数 → 输出新文件，原文件不动，
产物落在源文件旁边、同名自动编号。工程模式下这些单文件工具连同字幕 / 音轨菜单一起收起。

| 菜单项 | 作用 | 要点 |
| --- | --- | --- |
| 格式转换… | 把当前文件或整个文件夹转成别的格式 | 目标格式是可搜索的下拉；来源能切成「文件夹…」做批量，逐个串行执行 |
| 替换或删除音轨… | 换 / 删内置音轨、改语言标签与默认轨 | 画面流复制，只对音频单路转码 |
| 内嵌字幕… | 把外挂字幕装进容器 | 画面与音轨流复制，字幕单路转换 |
| 生成代理文件… | 生成低码率预览副本 | 三档规格（480p / 720p / 1080p），码率上限可以自填（留空用档位默认的 1.5M / 3M / 6M，写 `3M` 或 `3000k` 都认）；工程模式下素材比序列大、旁边有 `<原名>.proxy.mp4` 时预览会自动换代理（选中那段片段会标出「代理」），导出始终用原片。素材库里选中一个视频素材能「生成代理…」，已有代理时变成「重新生成代理…」并原地覆盖；不选或选多个时那颗按钮变成「补代理…」，把整个库里比序列大、还没有代理的素材串成一条队列慢慢补（列表上方那一行有进度、「跳过」当前一条与「全取消」），设置里还能让它导入后自动开始 |
| 把列表拼成一个文件… | 按播放列表顺序拼接 | 列表里至少两个文件才可用 |

### 设置窗口

所有偏好都收在一个模态窗口里（菜单「设置 → 设置…」，或按 `A` / `?` 直达对应页），
左侧标签切换分组，改动立刻生效并落盘，没有「确定 / 取消」：

| 标签页 | 内容 |
| --- | --- |
| 画面设置 | 画面比例、旋转、镜像 |
| 视频设置 | 渲染模式、解码方式、播放显卡 |
| 播放设置 | 循环模式、窗口置顶策略、剪辑预览是否自动用代理、导入后是否自动补代理 |
| 渲染缓存 | 预览是否用渲染缓存、目录容量上限、补缓存队列与进度、清理缓存 |
| 文件关联 | 设为默认播放器、撤销关联、启动时自动维护 |
| 快捷键设置 | 全部键位表 |
| 关于 | 版本、技术栈与运行环境 |

左列底部的「恢复默认设置」把这些页里的选项拉回出厂值；音量、窗口大小、面板宽度
这些「用着用着调出来的」值不受影响。

### 视频渲染与解码

「视频设置」页里三组单选，都随偏好保存：

- **视频渲染模式**：两档走的都是同一条软件渲染路径，区别只在内部渲染分辨率——
  性能模式把高度封顶在 720（全屏看高清时省下的缩放与回读是耗电大头），
  稳定模式按窗口实际尺寸渲染，画面更细腻。
- **视频解码模式**：分别对应 mpv 的 `auto-safe` / `auto-copy` / `no`。三档都用
  「拷回内存」的变体，因为主画面走软件渲染，零拷贝的硬件帧接不住。
- **播放显卡**：只在 Windows 上能列出（`EnumDisplayDevicesW`），写进 mpv 的
  `d3d11-adapter`；只影响硬件解码那一路，软件解码时与显卡无关。

### 设为默认视频播放器

设置窗口「文件关联」页的「设为默认视频播放器」会把本程序登记为 60 个格式
（54 个视频容器 + 6 个播放列表格式）的候选。三个平台的机制完全不同：

| 平台 | 落点 | 用户还要做什么 |
| --- | --- | --- |
| Windows | `HKCU\Software\Classes` + `Capabilities` + `RegisteredApplications` | 要。在打开的「默认应用」里选一下本程序 |
| Linux | `~/.local/share/applications/*.desktop` + `~/.config/mimeapps.list` | 不用，注册即生效 |
| macOS | `.app` 的 `Info.plist` + LaunchServices | 不用，注册即生效 |

**Windows 上这一步没法静默完成**：`UserChoice` 带哈希校验，程序只能把入口放进「默认
应用」列表，剩下那一下必须由用户亲手点（见 `docs/adr/0002`）。

**macOS 必须先打包**：`bash scripts/bundle-macos.sh` 生成 `dist/ngy-video-player.app`，
再从包里启动。裸二进制在 LaunchServices 眼里没有身份，注册会直接报错并给出这条指引。

同一页里还有「移除本程序的文件关联」用于撤销，「启动时自动维护文件关联」控制每次启动
是否按当前可执行文件的路径重写一遍——关掉之后，默认播放器被别的软件拿走也不会再改回来。

线程模型：

- **引擎线程**：`mpv_wait_event` 循环，处理命令、属性变化、文件结束；
- **取帧线程**：持有 `mpv_render_context`（软件渲染），有帧就渲染到 64 字节对齐的
  缓冲，包装成 `RenderImage` 推给界面；
- **主线程**：GPUI 渲染。后台通过 `futures::mpsc` 单向推事件，
  `AsyncApp` 不是 `Send`，跨线程只能走这条通道。

## 已知限制

- 软件渲染路径在高分辨率 + 高帧率下受内存带宽限制；1080p60 无压力，4K120 需要
  硬件后端（接口已预留）。
- HDR（PQ/HLG）素材在导出与预览里都会转成 SDR（`zscale` + `tonemap=hable`，见
  `docs/adr/0007`）：成片固定 bt709，不做 HDR 输出。判定只看传递曲线，标错的素材不会
  被硬转。
- 硬件解码默认关闭（`hwdec=no`）：软件渲染下 hwdec 要把帧从显存倒回内存，通常更慢。
  需要的话在设置窗口的「视频设置」页里切到智能解码或硬件解码，不必手改配置文件。
- 播放显卡只在 Windows 上能列出（`EnumDisplayDevicesW`），且只对硬件解码这一路有意义；
  Linux/macOS 显示「系统自动选择」。
- 单文件分发的 exe 约 220MB（约 116MB libmpv + 约 90MB ffmpeg），首次启动要多花一次
  解压的时间写进缓存目录。不想要这个体积就 `NGY_EMBED_MPV=0 NGY_EMBED_FFMPEG=0
  cargo build --release`，改回「依赖放在 exe 旁边 / 用系统里的 ffmpeg」的分发方式。
- 裁切的 HDR → SDR 色调映射依赖 ffmpeg 的 `zscale` / `tonemap` 滤镜；换成精简版
  ffmpeg 时可能报错，取消勾选「HDR → SDR」或改用无损流复制即可。
- 元数据编辑固定输出 mkv：章节与字体附件在 mp4 里的写法各不相同，只维护一套落点。
  旋转元数据写不进去（ffmpeg 会静默丢弃 mkv 的 `rotate`）。
- 工程模式的预览最多合成**两路**视频（CPU 软件合成，ADR 0008 的架构 A）：三条以上只叠
  最上面两路并提示一次；画布尺寸跟着窗口走，旋转元数据在合成路径上不生效；效果栈 / 调色 /
  关键帧的画面变换还没进合成链，只有导出才看得出。转场仍是「淡到黑再淡回来」的近似
  （窗口跨在接缝上，两侧各一半时长），空档压黑是界面叠层。声音同时最多**四路**：每条音频轨
  一个纯音频 mpv 实例，混音交给系统混音器（不是自研引擎，没有重采样与总线），超过四路的轨
  先不响并提示一次；音频轨有内容时主画面的原声被压住。轨道音量是振幅倍数（-12 / -6 / 0 /
  +6 dB 四档，没有自定义输入），导出写进 `volume` 滤镜、预览乘到 mpv 音量上，两边同源但
  不保证逐样本一致。换素材时的加载落在关键帧上，之后靠一次精确 seek 校正。
- 转场只作用于画面（`xfade`），音频侧仍是硬切；只支持同轨紧邻的片段（中间有空档就得先接上），
  并且一次只能跨一个接缝——叠三段的长溶解得拆成两次。
- 多路合成是 **CPU 合成**：`NGY_COMPOSITE_BACKEND=gpu` 只会退回 CPU 并说明原因，GPU 后端
  还没实现（见 `docs/adr/0010`）。1080p 两路可用，三路以上只叠最上面两路。
- 速度曲线（时间重映射）目前只有模型：工程里能存一条 `SpeedCurve`、能算出时间线时长，
  但导出、预览与界面都还用常量档位（`ClipItem.speed`）。
- 遮罩（矩形 / 椭圆 / 路径、羽化、位移）目前只有模型与存盘：工程里能存、能读回，
  但**导出与预览都还没用上**，界面上也没有画形状的入口。
- 音量分三层：片段音量 × 轨道音量自动化 × 轨道推子（都是线性振幅，连乘）。轨道声像在
  导出时按等功率法则落成 `pan`；**预览侧还没跟**——预览听到的是推子与自动化起点，听不出
  声像与自动化曲线。混音台界面（推子滑块、电平表、自动化点编辑）也还没做，现在只能靠
  工程文件里的 `gain` / `pan` / `automation`。
- 素材搜索只支持「并且」与否定，没有 OR、括号和正则：素材库通常几十到几百条，
  把不要的挑掉就够了。标签与合集不进撤销栈（它们不是剪辑动作），但会触发自动保存。
- 关键帧缓动在导出侧是**按 8 段折线采样**的（ffmpeg 表达式里解不了三次方程），预览走
  真曲线；两者的差值远小于 1/255，但不是逐像素相同。不透明度的缓动导出时会丢——`fade`
  只有线性淡变，曲线只影响预览。
- 渲染缓存只覆盖单路预览：两条视频轨同时有画面时走多路合成，那一路仍然直接解码原片，
  效果看不到。缓存文件不带声音（音频仍由音频轨那几路实例出声），也只缓存「倍率 1x、
  无片尾定格」的片段。补缓存要手动点一次（编辑后不自动重渲），所以改完效果参数要记得
  再点一遍。
- OTIO 只交换两边都有的东西：轨道顺序、片段入出点、空档、转场与标记。字幕轨、效果栈、
  关键帧、调色、片尾定格与轨道音量存在 `metadata.ngy`，别的软件读不到（本程序能原样读回）。
  导入时对方的时间线会变成**一条新序列**，素材按 `target_url` 登记进工程，缺文件标「缺失」；
  认不出的转场按交叉溶解、认不出的效果丢掉并在提示里点名。变速写成 OTIO 的
  `LinearTimeWarp`，对方软件认不认取决于它自己。导出 / 导入都还没在 Resolve 与 Premiere
  里实测过。
- 转场时长上限是 2 秒：更长的溶解在成片里已经不像转场，不如换个剪法。
- 片段效果只在导出时生效，预览看不到；插帧（`minterpolate`）是逐帧运动补偿，
  几分钟的片子可能要跑很久，面板底部会按序列帧率提示。
- 调色同样只在导出时生效，而且只做一级校色：亮度 / 对比度 / 饱和度 / 色温加一条 LUT，
  没有色轮、HSL 限定器、遮罩跟踪与节点。色温是 `colorbalance` 的红蓝偏移近似，不是
  以开尔文为单位的真色温。
- 字幕只在导出时由 libass 排版：预览是一层界面文字，不显示字体差异与描边，字号按窗口
  缩小一档；文本里的 `{` `}` 会转成圆括号（避免被当成 ASS 样式标签），换行写 `\N`。
  不做逐字动画、卡拉 OK、字体嵌入管理。
- 软字幕的样式随容器打折：mkv 存完整 ASS，mp4 / mov 只能 `mov_text`（字体、描边、位置
  会丢），webm 之类不认这两类的容器请选「烧录」。软字幕是成片里的一条独立轨，播放器
  可以关掉；烧录则改不了。
- 字幕条目是独立的序列时间区间：切割 / 波纹删除 / 变速都不会带着它一起动，改完片段
  要手工调起止。同一轨的条目不能重叠，多条字幕轨按轨道顺序叠放。
- 多条序列共享一份界面状态与撤销栈：切换后播放头归零、选中 / 工作区清空、撤销栈
  重置（不能跨序列撤销），缩放与滚动沿用当前视图。改名 / 删除序列不进撤销栈，
  删错了只能从工程文件或它的 `.bak` 找回。
- 新序列沿用当前序列的分辨率与帧率，建的时候不选规格；不支持嵌套序列，也不能把
  一条序列当素材插进另一条。
- 工程格式升到 v2（`sequences` 列表 + `active_sequence` 指针）：老工程会自动读成
  「只有一条」，但旧版本播放器打开 v2 工程会提示版本过新。
- 效果里的水印打的是片段自己的名字（没有输入框），要自定义文字用字幕图层。
- 修剪工具是会话状态（不进工程、不进撤销栈），重开程序回到 `V` 修剪；滚动编辑只认「本段
  与后一段的接缝」，拖左端时退回普通修剪。双画面窗口在**松手之后**才取帧（拖动中只有一条
  落点竖线），取帧失败时
  两格显示「这一帧取不出来」而不是报错弹窗；窗口不会跟随后续的其它操作自动关闭，点它或
  再修剪一次才会换掉。修剪按 1:1 换算素材时间，片段带变速（倍率 ≠ 1）时收放的长度与拖动
  的像素不完全对应。波纹修剪 / 滚动编辑只作用于同一条轨，其它轨道不跟着动。
- 关键帧标记只能在片段自己所在的轨道上拖（拖到别的轨道不生效）；挪到已有标记的时刻会
  合并成一个点。不透明度只认 0 ↔ 1 的淡入淡出（中间值 `fade` 表达不了，那一段导出时
  会被跳过）。
- 素材库的「缺失 / 文件已改动」只在打开面板和导入完成时重算一次：程序运行期间删掉或
  换掉某个文件，要收起再打开一次面板才看得出来。封面按素材第 0 秒取，纯音频素材没有封面。
  从素材库拖到轨道只落在**被拖到的那一条轨**上：视频素材拖到视频轨不会自动把声音也排进
  音频轨，要连画面带声音一起排用「导入到时间线…」。插入只影响被拖到的那一条轨：
  其它轨道不会跟着后移，多轨对齐还得手工来。波纹删除同样只作用于片段所在的轨道。
  三点编辑一次只放一路：有画面的素材进视频轨，它自带的声音不跟着排进音频轨（四点编辑
  才会把声音一起排到目标音频轨；视频素材本身不带音轨时自然只有画面）。四点编辑的落点
  轨道只认图钉与「同类第一条没锁的」，不会自动新建轨道——没有空轨时先加一条。
- 「收集素材到工程目录」是把素材**复制**进 `<工程名>_assets/`，不压缩、不移动原文件；
  有素材缺失时直接拒绝，不会打出半个包。
- 关窗口（标题栏 ×）现在也会先问「保存 / 不保存 / 取消」：gpui 0.9 起有
  `on_window_should_close`，拦下来之后复用菜单「退出」那条确认路径。`.autosave` 仍然
  保留——进程被强杀时它是唯一的退路。

文件关联相关的限制：

- **不会自动抢默认**：Linux/macOS 上注册即生效，Windows 上只能把本程序送进「默认应用」
  列表，最后一步由用户点。
- **macOS 的「移除关联」只撤声明**：系统没有「把默认还回去」的接口，已经选定的默认要
  用户自己在 Finder 的「显示简介 → 打开方式」里改。
- **macOS 没有应用图标**：`.icns` 还没生成，Dock 里是通用图标。
- **Linux 依赖 shared-mime-info**：系统里没有 `/usr/share/mime/globs2` 时只认内置表里的
  二十来个常见格式，其余扩展名会被跳过而不是猜一个 MIME 蒙上去。
